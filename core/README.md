# studio core

Ядро студии: HTTP-сервер раздаёт собранный веб-интерфейс и запускает
плагины чат-клиентов, с которыми общается через stdin/stdout.

## Два режима фронтенда

| Что запустить | Где смотреть | Что это |
| ------------- | ------------ | ------- |
| `npm run dev` | http://localhost:1081 | разработка: HMR, правки sass/js без перезагрузки |
| `npm run build` + `go run .` | http://localhost:1080 | продакшен: раздача `dist/` |

```bash
npm install          # один раз: vite + sass-embedded
npm run dev          # HMR на :1081
npm run build        # сборка фронтенда в dist/
go run .             # ядро на :1080: раздаёт dist/ и запускает плагины
```

Порт можно сменить: `go run . -addr :9090`.

Запросы с `/api` из дев-сервера Vite проксируются на :1080 — когда появится
API ядра, менять ничего не придётся.

## Сборка

Всё собирается из корня репозитория через Makefile:

```bash
make            # ядро и все плагины под текущую ОС
make windows    # то же под windows (ядро studio.exe, плагины *.exe)
make linux      # то же под linux
make release    # обе платформы в dist/<goos>-amd64/
make test       # тесты ядра и плагинов
make clean      # убрать бинарники
```

Кросс-платформенность учтена в коде: на unix плагин — `goodgame`, на windows —
`goodgame.exe`, ядро ищет своё имя платформы; проверка бита исполнения
используется только на unix.

## Плагины

Плагин — отдельный Go-модуль в `plugins/chat/<имя>/`, в нём же собирается
бинарник с тем же именем. Ядро при старте:

1. сканирует `plugins/chat/` (флаг `-plugins`, по умолчанию каталог репозитория);
2. находит `<имя>/<имя>` или `<имя>/<имя>.exe`;
3. запускает бинарник и печатает относительный путь и всё, что плагин пишет в
   stdout;
4. при остановке (Ctrl-C) шлёт `quit` и ждёт выхода, убивает только если плагин
   не завершился сам.

Плагин, который не запустился, не роняет ядро — ошибка попадает в лог.

Логи, в том числе сообщения плагинов, идут в **stdout**: `./studio > studio.log`
заберёт всё, stderr остаётся пустым.

Модули ядра и плагинов связаны через `go.work` в корне репозитория.

## Настройки

`config.json` рядом с ядром (флаг `-config`, переменная `STUDIO_CONFIG`):

```json
{
  "kind": "config",
  "version": "1.0",
  "plugins": {
    "chat": {
      "goodgame": {
        "enabled": true,
        "options": {
          "channels": []
        }
      }
    }
  }
}
```

Значения опций лежат в объекте `options` плагина: `enabled` — это поле ядра,
а всё внутри `options` задаёт сам плагин своей формой. Ключ опции совпадает с
ключом в `config.json`, поэтому значения возвращаются плагину без
преобразований.

- Файл пишется атомарно (временный файл + `rename`) с правами `0600`: там
  будут токены и пароли.
- Неизвестные разделы и ключи не теряются при сохранении: ядро их не
  понимает, но и не выкидывает.
- Неверное значение не ломает запуск: ядро пишет в лог, что не так, и
  подставляет значение по умолчанию из схемы плагина.
- Весь JSON — через `encoding/json/v2` (в Go 1.27 он штатный). Ключи map'ов
  сортируются опцией `json.Deterministic`, иначе каждое сохранение
  переставляло бы ключи и портило diff.

## Протокол ядро ↔ плагин

NDJSON: одно JSON-сообщение в строке, `\n` — разделитель.

```
ядро → плагин   {"type":"get_info"}
плагин → ядро   {"type":"info","id":"goodgame","name":"GoodGame","options":[...]}
ядро → плагин   {"type":"set_options","values":{"channels":["general"]}}
плагин → ядро   {"type":"ack"}
плагин → ядро   {"type":"log","level":"info","message":"..."}
ядро → плагин   {"type":"quit"}
```

Плагин описывает свою форму сам — ядро только рисует её:

```json
"options": [
  { "key": "channels", "type": "tags", "label": "Каналы", "hint": "Enter — добавить канал" }
]
```

Типы: `text`, `password`, `number`, `bool`, `select` (с `choices`), `tags`
(мульти-поле: сколько угодно значений). Атрибуты: `label`, `hint`,
`placeholder`, `required`, `default`, `choices`. Ключ `enabled` в схеме не
участвует — это поле ядра.

Неизвестные ядру типы сообщений и ключи опций не считаются ошибкой: старый
ядро не должен падать на новом плагине.

## Флаги ядра

| Флаг | Переменная | По умолчанию | Назначение |
| ---- | ---------- | ------------ | ---------- |
| `-addr` | `STUDIO_ADDR` | `:1080` | адрес прослушивания |
| `-config` | `STUDIO_CONFIG` | `config.json` рядом с ядром | файл настроек |
| `-plugins` | `STUDIO_PLUGINS` | `plugins/chat` | каталог с плагинами |
| `-web` | `STUDIO_WEB` | `dist`, иначе `html` | каталог с `index.html` |
| `-shutdown-timeout` | — | `5s` | ожидание активных запросов при остановке |

Если `dist/` нет, ядро отдаёт исходники из `html/` и пишет в лог
предупреждение — такая страница будет без стилей.

## Структура фронтенда

```
html/
├── index.html        каркас: сайдбар разделов + две панели
├── js/app.js         данные чат-клиентов и рендер (сейчас заглушка)
└── sass/
    ├── app.sass      точка входа: @use всех партиалов
    ├── _tokens.sass  цвета, метрики, шрифты
    ├── _base.sass    сброс и базовая типографика
    ├── _layout.sass  сетка страницы, сайдбар
    └── _options.sass список клиентов, форма опций
```

Партиалы с подчёркиванием не собираются в отдельные файлы — это делает sass
сам через `@use`. Файл с точкой входа импортируется из `js/app.js`
(`import '../sass/app.sass'`), поэтому Vite подхватывает изменения стилей и
применяет их на лету.

Настройки чат-клиентов пока живут в `localStorage` — это прототип. Когда будет
API, в `app.js` достаточно заменить `CHAT_CLIENTS` на `fetch('/api/plugins/chat')`.

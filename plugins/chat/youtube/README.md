# YouTube chat plugin

Плагин читает чаты прямых эфиров YouTube. Ключ не обязателен: с ним работает официальный путь, без него — резервный. Резервный включается сам, когда официальный недоступен.

## Настройки

- **YouTube API key** — необязателен. Ключ Google Cloud project с включённым YouTube Data API v3. Без него плагин читает резервным путём и остаётся в сети.
- **Каналы и стримы YouTube** — список, по строке на цель. Понимает ссылку на канал, @handle, ID вида UC…, ссылку на стрим (`watch?v=…`, `youtu.be/…`) и голый id трансляции. Целей может быть сколько угодно: эфир иногда идёт двумя трансляциями сразу — обычно короткой и обычной.

Разница между каналом и стримом не косметическая. Канал надо искать: он очнётся когда-нибудь сам. Стрим уже известен — к нему идут сразу, не тратя ни минуты и ни квоты.

Псевдонимы вида `youtube.com/c/имя` и `/user/имя` намеренно отвергаются. Это не @handle, и канал по такому имени может оказаться совсем другим — подписаться молча не на то хуже, чем отказать.

Пользовательский OAuth не требуется для чтения публичного live chat. Ключ передаётся в REST-запросах как параметр `key` и в gRPC metadata как `x-goog-api-key`.

## Два пути чтения

**Официальный** — gRPC server-streaming `liveChatMessages.streamList`. Дороже по квоте, но не требует ни браузерных страниц, ни их разбора.

**Резервный** — страница трансляции и её `get_live_chat` continuation. Ключ не нужен и не проверяется: эфир находится по фиду канала, чат читается с публичной страницы. Работает там, где официальный не работает, — в том числе без всякой регистрации.

Переключение происходит само и в обе стороны не требует перезапуска:

- **ключ негоден** (400, 401, 403) или кончилась квота — идём читать резервом;
- **поток открывается и умирает**, не отдав ни одного сообщения (три обрыва подряд) — тоже идём читать резервом. Ключ тут ни при чём, чинить это можно только сменой пути.

Галочку **резервное чтение** можно снять, и тогда плагин не станет молча переключаться: путь останется тем, который выбран, и ошибка будет видна.

## Поиск эфира и квоты

Канал разрешается в ID через channels.list (одна единица квоты) либо страницей канала. Затем эфир ищется официальным `search.list` с фильтрами `channelId`, `type=video`, `eventType=live`, не чаще раза в минуту.

Поиск официальным способом ограничен **пятью попытками**. Дальше плагин переходит на фид канала: тот не стоит квоты и ждать умеет сколько угодно. Пять минут ожидания — срок осмысленный: эфир либо уже идёт и находится с первой попытки, либо человек его ещё не запустил и ждать дальше официальным поиском незачем.

У `search.list` отдельная базовая квота — 100 вызовов в сутки на Google Cloud project, и она общая для всех установок, работающих через этот ключ. Именно поэтому официальный поиск ограничен, а не бесконечен.

## Ограничения

- Только публичные эфиры с доступным чатом; отключённый чат прочитать нельзя.
- Резервный путь разбирает публичную страницу, поэтому сломается, если YouTube поменяет разметку. Это цена работы без ключа и без регистрации.
- Переподключения используют задержку с экспоненциальным ростом, чтобы не долбить ни поток, ни квоту.

## Реализация

Потоковые protobuf-типы `streamList` лежат в `internal/ytproto`; они сгенерированы из `chatstream.proto` в проекте codigolandia/live-quest (https://github.com/codigolandia/live-quest) и поставляются с его MIT-лицензией. Плагин использует стандартную библиотеку Go, gRPC и Protocol Buffers.

Пользовательский текст попадает в `message.text` / `message.src` как есть: небезопасный HTML из содержимого не строится.
